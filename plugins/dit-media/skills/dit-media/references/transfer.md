# 批量传输与工具校验

Windows 优先 FastCopy，Linux/macOS 优先 rsync；缺失时按主文的平台选择规则安装，不为统一工具名强行增加运行环境。复制、并行 I/O、重试及哈希校验由工具承担；脚本只衔接清单、日志核对、改名和索引。

## 执行顺序

1. 固定源→目标映射，按目标文件系统准备唯一临时目录，以原名批量复制；同名源文件须分组隔离。已有且验证一致的文件不重拷。
2. 使用工具的原生并行 I/O 和校验，依据包含校验阶段的总耗时调整并发，不默认多开进程更快。
3. 本次拷卡的全部复制与校验通过后，再按映射统一同卷改名、同步侧车并发布索引。保留哈希和必要结论，清理本任务临时产物。

核对退出码、错误数、逐文件校验结果、算法、数量及源文件状态。复用可靠结果，不再手写哈希或重复扫描。中断后按实际文件和日志对账；被跳过、长度相同或进程成功，均不能单独证明某个文件已验证。失败项保留续作状态，不发布为已归档。

## Windows 本地盘或 SMB：FastCopy

- 使用 `fcp.exe` 等待批处理完成，开启 `Verify`，选择库要求的算法。默认可能为 xxHash3，不能记为 SHA-256。
- 保留用户原配置；可将已有程序置于任务临时工具目录，配合 [专用配置](../assets/fastcopy/FastCopy2.ini) 使用。该配置已在 4.2.1 验证，`hash_mode3="2"` 对应 SHA-256；工具或配置改变时用已知内容的小样确认，不每次重做测试。
- 调用示例；路径参数分别传入并正确引用，具体选项以已安装版本帮助为准：

```text
fcp.exe /cmd=noexist_only /verify /disk_mode=diff /speed=full /bufsize=256 /no_ui /balloon=FALSE /postproc=FALSE /log /logfile=<汇总日志> /filelog=<逐文件日志> /srcfile=<UTF-8源文件清单> /to=<同卷临时目录>
```

`diff` 磁盘模式适用于源卡与 NAS 等不同设备；同物理盘按实际情况选择。采用工具的重叠 I/O 和复制／校验流水线，不以多个自写复制进程替代。检查退出码 0、错误数 0及清单内每个文件的校验成功记录和所需哈希，不把跳过的文件算作本次已验证。

## Linux/macOS：rsync

优先使用 rsync，先检查已安装版本及支持的选项。rsync 的传输校验、`--checksum` 对已有文件的比较、目标落盘读回校验是不同环节，默认校验不等于 SHA-256。库另有算法或读回要求时，交给支持该要求的工具，不能凭默认成功状态宣称满足。

参考：[FastCopy 帮助](https://fastcopy.jp/help/fastcopy_eng.htm)、[rsync 手册](https://download.samba.org/pub/rsync/rsync.1.html)。
