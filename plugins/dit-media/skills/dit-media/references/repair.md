# 损坏视频与工具

仅在需要分析/修复时读取。不要给普通归档增加修复步骤。

## 工具发现

- 优先查找现有`ffprobe`、`ffmpeg`、ExifTool；它们用于参数、解码验证和厂商元数据，不必复制进每个项目。
- 查找目标环境已有共享工具目录，再按当前操作系统选择可运行版本；只读NAS或不兼容的平台可在本地临时目录处理。没有工具时再从官方来源取得，不将用户视频上传在线修复网站。
- untrunc官方：https://github.com/anthwlock/untrunc 。工具可位于使用者指定的共享或本地工具目录，例如 `<工具根>/untrunc`；先检查当前平台是否兼容，不作为必需路径或固定版本。

## 修复判据

1. 缺失`moov`常见于录制中断，但先排除读取权限、源复制不全、工具大文件限制。侧车XML缺失与MP4内部索引缺失是两种问题。
2. 损坏原件不可覆盖。复制到临时目录；选同机、尽量同分辨率/编码/色深/帧率的正常片作参考。短参考片不充分时，用较长匹配参考再比较结果。
3. 先查看当前工具帮助。一个适用的调用是：`untrunc -n -s -dst "输出.mp4" "参考.mp4" "损坏副本.mp4"`。所有路径作为独立参数传入。没有新证据时不无限更换选项反复尝试；当现有证据已不足以选择有意义的下一步时，报告已恢复范围与限制，必要时索取更匹配的参考，不设机械的尝试次数。
4. 修复成功不能只看退出码或能打开。用ffprobe检查轨道、帧数、时长；用ffmpeg完整解码并检查退出码/错误日志，抽样查看实际画面。音频需要时检查音画同步；用户不需要音频时可直接复制视频流输出无音轨版，避免不必要转码。
5. 修复可能沿用参考片的帧率、时间基准、封面和时间字段。去除不属于原片的参考元数据；无法确认的拍摄时间不凭参考片或文件名伪造。若已有推定时间字段，必须披露其依据，修改需与用户范围一致。
6. “常速”只确认拍摄方式R，不能独立确认25/30/50/60P。原时间索引损坏时，参考帧率只能标注为推定；不得为音画等长随意拉伸视频，也不能承诺找回从未写入的画面。
7. 候选与原件分开，沿用目标库的异常素材位置；没有约定时可以使用日期目录下的`_待检查`，无需固定再嵌一层目录。日期未确认时先留在任务临时目录并询问，不强行归入某天。原件和修复版分别登记哈希和关联；短备注说明无音轨、推定帧率、恢复范围等实质限制。
8. 校验交付版后按主流程清理临时产物；影响使用的修复结论只需摘要写入索引。

## 设备元数据线索（仅对匹配设备适用）

- 用户确认拍摄D-Log M时可沿用目标库的DLOGM标签；并非所有DJI视频都是D-Log M，也不假定它有Sony式XML。
- Sony XML的`CaptureGammaEquation`、`CaptureColorPrimaries`及`RecordingMode`可辅助区分S-Log3、直出和延时；LUT文件引用可能只是监看设置。
- 报告实际恢复帧数/时长；文件系统时间跨度不能证明同样长的录像已写入。
