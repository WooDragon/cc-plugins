# 视频归档与 DIT

目标：素材可定位、来源可追溯、复制可验证；目录保持简洁，重复执行不会产生重复副本或误覆盖。遵循用户现有命名规则，不另造完整资产管理系统。

## 边界

- 先读素材库相关规范、现有索引说明和代表性历史命名。**修改任何规范性文件前，必须给出最小变更内容并取得用户明确许可。**普通整理授权不包含修改规范；现有索引说明也属于规范。需要调整时继续完成不受影响的工作，将建议集中提出，不自行改写。
- 用户明确确认的实际拍摄日期、色彩及用途优先于机器记录；矛盾保留为简短备注。用户仍不确定时，列出具体证据，询问后再改动有争议的部分。
- 不自动清卡、不自动删除短片或疑似重复文件。用户授权删除的范围不扩大到其他副本。一次性的“删除不足1秒”不成为未来默认策略。
- 不把挂载盘符、用户名、项目日期、序号或设备路径写死。每次确认源根目录、素材根目录及工具位置；根目录可以是盘符、UNC或挂载目录，执行时解析完整路径，索引只存相对路径。不能用旧会话的盘符自动选择本次设备。

## 固定工具

重复操作调用 [标准化工具](references/tools.md)：源清单与变化检查、复制日志核对、同卷改名归位、索引预检与发布。每次只准备任务数据和参数，不重写执行脚本；缺失能力应扩展共用工具并补测试。设备、日期、色彩与原片关联的判断结果作为输入，不由工具猜测。

## 工作流程

### 1. 盘点和判读

- 限定本次设备、日期及媒体范围。读取根目录规范和指定目录，不无差别扫描整个NAS。映射盘不可见时检查执行环境与权限，不直接判定素材缺失。
- 记录源名、大小、技术参数、拍摄时间依据、配套文件和现有目标。同卡可能混用设备，逐文件依据内嵌型号及厂商侧车识别，不凭目录名或连续编号归为同一设备。默认处理视频；用户要求照片分流时，按拍摄日期归入指定照片库，默认保留原名。LRF等代理按用户范围取舍，SRT、Sony XML等配套文件随视频保留，视频改名时同步主文件名，内容不改写。
- 索尼卡（如 A7CR）照片与视频分目录：照片通常在 `DCIM/<编号>MSDCF`，视频及 XML 在 `PRIVATE/M4ROOT/CLIP`；按实际卡结构分别盘点，不能只扫描 DCIM。`Cxxxx.MP4` 通常配套 `CxxxxM01.XML`，归档时按库规范同步主文件名；设备与日期仍逐文件核实。
- 用 ffprobe 确认分辨率、精确帧率、像素格式、音轨和时长；用 ExifTool/厂商侧车补充拍摄模式、标称码率和色彩。支持大文件与Unicode路径，避免把分析器限制误诊为损坏。
- 区分拍摄日期与文件复制/修改时间、UTC与本地时区。相机文件名和内嵌时间都可能设置错误；有冲突不靠单一来源定案。目录归属、原始文件名、内部时间是三件事，不为统一外观而改写媒体元数据。
- 依据实际色彩信息命名，不把监看LUT引用当作已烘焙风格。灰片也可能在通用容器标签中显示BT.709；不能只凭该标签判断。元数据不足时可采用用户明确确认，仍有歧义则询问。
- 常速R、高帧率待后期放慢、已放慢SL和延时TL分别判断。色深看像素格式，容器的24bit字段不等于单通道24bit。
- 延时与拼接原片先按分组编号、拍摄时间和厂商元数据核对对应成片，不仅凭扩展名分流。延时可能没有字幕侧车；缺少侧车不视为缺件，色彩仍依据可靠元数据或用户确认。
- 延时原片随对应视频归入视频库，放在与视频同名（不含扩展名）的独立目录；拼接原片随对应成片归入照片库，每组放在与成片同名（不含扩展名）的独立目录，原片保留原名。成片改名时同步原片目录与索引关联；对应关系不明时保留原分组，不猜配或混放。
- 码率优先使用可靠标称值；规范允许使用实测值时注明依据。短视频平均码率可能很低，不能据此猜测相机档位。设备缩写和色彩标签优先沿用现有规范，无需另建映射表。

### 2. 形成并检查变更清单

- 在一个任务临时目录中准备源→目标映射；先检查目标唯一、日期、设备编号、侧车配对、空间和源可读性，再执行。编号和目录结构沿用目标库约定；无约定时提出最小方案，不默认套用逐日编号。不为补齐空号重排旧素材。
- 已有同名或可能已归档的文件先比较来源、大小与必要的哈希。同名异内容停止该项，不覆盖；已有且验证一致则跳过，不另建重复副本。失败重试前重新检查磁盘实际状态。

### 3. 执行和验证

- 平台选择：Windows 优先使用 FastCopy，Linux/macOS 优先使用 rsync。先检查现有工具；缺失时可自主从官方来源或可信包管理器安装，无需仅因安装工具再次询问，但仍遵守执行环境的权限要求。

- 优先使用成熟工具批量复制和校验，复用其并行I/O、错误处理与校验日志；不手写复制、哈希或重试逻辑。清单、日志核对、改名和索引衔接使用本技能固定工具。先固定映射，以原名完成本次拷卡的全部复制与校验，再统一同卷改名、同步配套文件并更新索引，不逐文件边拷边改名。工具用法见 [传输工具](references/transfer.md)。
- 新复制使用与最终目录同一文件系统内的唯一临时目录。沿用库规定的校验算法，无规定时采用SHA-256；优先由复制工具完成，必要时调用标准校验工具。确认源在读取期间未变化，直接复用可靠校验结果，不重复全量读取，也不把中断产物记作已归档。
- 同一文件系统内仅改名/移动时，不转码或改写内容，核对数量、大小、唯一目标及配套文件。跨卷、跨共享或工具可能执行复制时，按复制流程校验后才移除已授权移动的源文件。仅核对名称和长度不能写成“哈希一致”。
- 移动/删除前验证解析后的完整路径位于明确授权目录，用LiteralPath或等效API处理特殊字符；不拼接跨shell的破坏性命令。
- 先完成媒体操作，再发布对应索引。索引先写临时文件，校验后替换；如中断，基于现存文件和临时清单对账，不凭旧计划盲目重跑。涉及多个文件的操作不假定具备事务原子性。
- 损坏文件先保存原件，按需读取 [修复与工具](references/repair.md)。修复版单独登记并关联原件，不冒充相机原片。

### 4. 精简索引与收尾

- 遵循现有精简索引；新建或获准调整时采用 [索引格式](references/index.md)。新建索引以短说明和统一清单为基线；不为本次任务附加批次目录、报告库或重复规范，不擅自简化其他库已有的必要交付结构。
- 校验所有受影响的当前路径、侧车、关联、数量和哈希状态。改名、移动、删除和修复都同步更新关联字段；来源字段保留历史位置，不因当前文件移动而改写；更新当前关联及必要备注。归档到正确日期不意味着内部时间也已纠正，报告需明确区别。
- 临时产物集中在一个任务目录，结果验证后清理重复清单、备份、试修文件、日志及一次性脚本；不散落到素材库，也不将其转移到其他目录长期堆放。
- 共用工具、测试和短用法随技能维护，不随单次任务清理；第三方工具与依赖保留在合适的工具目录并注明来源。仅一次性任务数据放临时目录，不将当次设备或路径固化为工具默认值。
- 清理只针对本任务生成且已确认不再需要的文件；失败未恢复时保留必要的续作状态，并向用户明确位置和下一步。用户文件、原素材和唯一修复成果不随临时目录删除。
- 最终简述完成项、验证方式、仍有疑问的元数据以及可打开的成果位置。报告中使用当前可访问链接；持久化索引不依赖本机挂载路径。不要把未验证的异地备份或RAID当作额外已验证副本。
