# 文档维护

在文档写入前强制预检、写入后强制自查，防止层位违规和索引腐烂。

平台兼容性：在 Claude Code 中，doc-gate 插件 hook 会自动执行 skill-gate/recall-gate；在 opencode 中，除非另行安装 opencode adapter，本 skill 只提供人工遵循的文档维护流程，不承诺自动门禁。

## 1. 操作类型判定

| 类型 | 判定信号 |
|---|---|
| **CREATE** | 新建文件；用户说"写文档"、"记录一下"、"补个手册"、"创建指南" |
| **MODIFY** | 编辑已有文件内容；用户说"更新文档"、"补充章节"、"修正步骤" |
| **RENAME** | 改变文件名或路径；用户说"重命名"、"移动到" |
| **ARCHIVE** | 废弃或下线文件；用户说"归档"、"不再使用" |
| **RESTRUCTURE** | 目录调整、索引重建、批量整理；用户说"整理目录"、"重建索引"、"文档体系治理" |
| **DEDUP** | 定期查重 / 去重审计；用户说"查重"、"文档去重"、"审计重复"，或发现两份文档高度相似 / 完全相同 |

一次操作可能组合多种类型（如 RENAME + MODIFY），对每种类型分别走检查单。

## 2. 通用原则

以下原则适用于所有文档操作，预检和自查时作为判定基准。

### 层位分离

理论/架构说明与可执行操作步骤是两类不同的文档。前者解释"是什么、为什么、边界在哪"；后者给出"怎么做、怎么验、怎么回滚"。两者不混写。

### 渐进式下沉

信息放在离变化最近、但不超出其复用范围的那一层。如果一段内容满足以下任意两条，就应该继续下沉而不是留在上层入口：

- 超过一个业务域才看得懂
- 包含具体命令或参数
- 会随版本、拓扑、节点变化而频繁变更
- 已经在下游文档有权威版本

### 上层克制

入口索引文件（如 CLAUDE.md）只负责路由和约束，不做内容载体。长流程、具体参数、操作细节不该出现在入口。

### 索引可判别

索引条目不是"文件名堆列表"。每个条目至少暴露：

- 业务域（它属于哪个系统或模块）
- 拓扑/场景（适用于哪种部署形态）
- 可观测判别特征（端口、存储类型、节点形态、关键依赖等运行时可直接观测的特征）

兄弟条目之间至少有一个稳定可观测特征不同。

### 命名即定位

文件名暴露业务域和场景，拒绝泛化动作词（deploy / update / fix）。命名应让人在文件列表中一眼区分兄弟项。

### 去重收敛

- **单一来源**：每个知识点 / 每段操作只保留一份权威版本，其余位置引用它（见「跨文档引用」），不逐字复制。多个文档重复引用同一理论或重复执行同一操作时，抽取到共享层；横切共性抽 shared，不重复堆叠。
- **跨项目共享**：跨项目复用的内容（命令片段、配置模板、导航说明）抽到上游权威源 / 共享层，下游用祈使式引用指向，不在各子仓库逐字复制——逐字复制会随时间各自漂移。
- **治理形态**：去重是低频人工审计，不是阻断式门禁。增量撞车由 recall-gate 写时召回覆盖；存量重复低频偶发，靠定期 DEDUP（§5.6）人工清即可。

### 跨文档引用

Claude Code 不会自动展开普通 Markdown 链接。被动引用（`> 详见 [链接]`）在执行时是死链。跨文档引用必须选用正确机制：

| 机制 | 适用场景 | 行为 |
|------|----------|------|
| `@path/to/file` | 仅 CLAUDE.md 系列文件 | 启动时自动内联展开（最多 4 跳） |
| `.claude/rules/*.md` + `paths:` frontmatter | 按文件路径触发的作用域规则 | 编辑匹配路径时自动加载 |
| Skill `references/` | 深度工作流前置知识 | skill 调用时整体加载 |
| **祈使式引用**（下方格式） | 普通 .md 文档互引 | 指令触发 Claude 主动读取 |

**祈使式引用格式**（普通 .md 中需要 Claude 实际读取目标时使用）：

```
> **前置阅读**：{目标文档一句话摘要}，
> {触发时机}必须先读取：
> [relative/path/to/target.md](../relative/link)
```

**选型决策**：常驻上下文 → `@path` 或 rules/；按需加载 → skill 或祈使式引用。优先原生机制，祈使式引用是兜底。

**反模式**：
- `> 参考：[链接]` / `> 详见 [链接]` — Claude 不会展开
- 普通 .md 中写 `@path` — 不会被识别
- 把共享内容直接嵌入业务文档 — 违反去重收敛

### CLAUDE.md 通用化原则（全局 vs 项目级分级）

CLAUDE.md 是 Claude Code 的配置入口，会注入任务上下文，是污染面最大的文档。维护任何 CLAUDE.md 必遵「通用化原则」，并按层级分两级强度。

**通用化四判据**（增删内容时逐条自问）：

1. **跨域性**：是否跨 2+ 独立场景生效？只对单一项目/框架/场景有意义的内容不该进 CLAUDE.md。
2. **稳定性**：是否确定后基本不变？短期实验、版本节点相关、随拓扑频繁变更的内容不该进。
3. **鲁棒性**：是否是高鲁棒的原则/约定，不因环境细节失效？
4. **只放原则**：是否只是原则/约定/路由，而非单任务的具体操作步骤？操作细节应下沉到对应 skill 或 docs/。

**分级强度**：

| 层级 | 路径 | 强度 | 要求 |
|------|------|------|------|
| 全局 | `~/.claude/CLAUDE.md` | 最严 | 四判据**全部**通过才可增；任何场景特定内容一律外移到 skill/docs。注入所有任务，改动需极度克制。 |
| 项目级 | `<project>/CLAUDE.md` | 普通 | 四判据作为参考；允许项目专属约定，但具体操作细节仍应下沉到 docs/。 |

> doc-gate 门禁在编辑全局 CLAUDE.md 时会给出「最高强度」提示——命中即套用上表全局一行的要求。

### 表述规范

写作与 review 时的判定基准，分两层：§A 歧义层（硬约束）、§B 排版层（次要，机械可判定）。见 `references/writing-standards.md`。

| 层 | 编号 | 条目 | 适用语种 |
|---|---|---|---|
| §A 硬约束 | A1 | 一句一事 | 中英通用 |
| §A 硬约束 | A2 | 明确主语 + 主动动词 | 中英通用 |
| §A 硬约束 | A3 | 术语统一 | 中英通用 |
| §A 硬约束 | A4 | 单一精确含义 | 中英通用 |
| §A 硬约束 | A5 | 术语需定义 | 中英通用 |
| §A 硬约束 | A6 | 名词群精简 | 中英通用 |
| §A 硬约束 | A7 | 程序性文本三要素（条件/动作/预期结果） | 中英通用 |
| §A 硬约束 | A8 | 肯定式优先 | 中英通用 |
| §A 硬约束 | A9 | 助动词受控（应/宜/可/不应） | 中英通用 |
| §A 硬约束 | A10 | 拼写变体一致 | 仅英文 |
| §A 硬约束 | A11 | 冠词完整 | 仅英文 |
| §A 硬约束 | A12 | 避免悬垂分词 | 仅英文 |
| §A 硬约束 | A13 | 豁免条款（代码/命令/标识符/产品名/法律文本/引文/路径原样保留） | 中英通用 |
| §B 次要 | B1-B5 | 中英间距、标点全半角、强调符、引号形式、连字符区分 | 中文/英文分列 |

需要每条的正反例、豁免边界与语种适用细则时，读取 `references/writing-standards.md`。

### 内置工具

doc-gate 插件包含两个零依赖 Python CLI 工具：

- **`tools/recall-gate.py`** — BM25 词法召回 + 链接图谱合并引擎。由 PreToolUse hook 自动调用，在首次编辑 .md 文件时执行三维分析（内容召回、孤儿检测、出链验证），以 deny-once-per-file 模式呈现结果。无需手动调用——编辑 .md 时 hook 自动触发，结果会在 deny 消息中展示相关文档列表。
- **`tools/docs-graph.py`** — 链接图谱独立 CLI（7 子命令：check / backlinks / links / orphans / hubs / related / export）。重命名、归档、重组操作的引用扫描步骤优先使用此工具。

**recall-gate 与 doc-maintenance 的协作**：recall-gate hook 在 skill-gate 之后运行。调用 doc-maintenance skill（写入 marker）后首次编辑 .md，recall-gate 会自动展示相关文档——Pre-flight 第 5 步「确认不存在已有文档覆盖同一内容」可直接参考此结果，无需额外手动搜索。

## 3. 项目适配

不同项目的文档结构各异。执行文档操作前，先判断项目的层位体系：

1. **探测文档框架文件**：检查项目根目录是否存在文档体系设计文件（常见命名：`文档系统设计框架.md`、`ARCHITECTURE.md`、`CONTRIBUTING.md` 中的文档章节、顶层 `README.md` 中的文档规范段落）
2. **有框架文件**：以项目框架为层位权威，本 Skill 原则作为补充。读取其层位定义、分类约定和维护检查单
3. **无框架文件**：以本 Skill §2 通用原则为默认基线，通过观察项目现有目录结构推断其层位约定
4. **CLAUDE.md**：Claude Code 项目均使用 CLAUDE.md 作为入口索引，这是通用标准
5. **CC 原生分层**：检查项目是否已使用 `.claude/rules/*.md` 或 CLAUDE.md `@path` 引用。有则遵循已有分层；新增文档时优先利用原生机制实现渐进式加载，不把所有内容堆入根 CLAUDE.md

## 4. 工作流

所有文档操作遵循三阶段流程。

### 4.1 Pre-flight（写前必做）

0. **实例化数据收敛扫描**（当待写入/修改的内容含主机名、IP、端口、账号、版本号等易变实例化数据时，强制执行）：
   a. 全局 grep 目标数据的所有出现位置（文件 + 行号）
   b. 判定是否已有单一事实源（权威文件）；若有 → 指向它，不重写
   c. 若无权威源 → 按渐进式下沉确定落地层：`docs/` 目录（长期稳定）> 项目 MEMORY.md 条目（中期动态）> 行内硬编码（禁止）
   d. 将权威版本写入单一来源文件
   e. 其余位置改为祈使式引用（格式见 §2「跨文档引用」），命令块保留可执行内容
   f. 内容已完全迁移的冗余文件整个删除，不留空壳
   g. 更新入口索引（项目 CLAUDE.md 文档表 / MEMORY.md 索引）
1. 判定操作类型（§1）
2. 定位对应检查单（§5）
3. 如项目有文档框架文件（§3），读取其层位定义
4. 确认目标文档应放在哪一层、文件名是否恰当
5. 如为 CREATE，确认不存在已有文档覆盖同一内容（recall-gate hook 会在首次编辑时自动展示相关文档列表，可直接参考其结果）

### 4.2 Execute（执行文档操作）

按检查单指导执行，写文档时遵循 §2 通用原则。

### 4.3 Post-flight（写后自查）

1. 逐项走检查单中的检查项，确认每项通过
2. 入口索引已更新（CREATE 补条目，ARCHIVE 移除条目，RENAME 修正条目）
3. 无断链引入（新增的链接可达，修改的路径已全局同步）
4. 如发现违规，立即修正后再报告完成
5. 若本次操作涉及实例化数据迁移，再次 grep 确认旧路径/旧值零残留
6. 检查是否存在内容已完全迁移的冗余文件（尤其 memory/ 目录）：确认为空壳则直接删除并记录，不确定则保留并在完成报告中标注 warning

## 5. 操作检查单

### 5.1 CREATE — 新增文档

**检查项：**

- [ ] **层级正确**：该信息是理论/架构说明还是可执行操作步骤？放进了对应的层级目录
- [ ] **文件名规范**：文件名暴露业务域和场景（如 `redis-sentinel-ha-deployment.md`），不使用泛化动作词（如 `setup.md`、`guide.md`）
- [ ] **入口索引已补**：所属入口索引文件已添加本文档的条目
- [ ] **兄弟可判别**：如同层存在功能相近的兄弟文档，索引条目已加入可观测判别特征以区分
- [ ] **无冗余重复**：该文档内容与已有共享文档不重复；若重复超 60%，应考虑抽取共享层
- [ ] **通用化检查（仅 CLAUDE.md）**：是否跨 2+ 场景？是否确定后基本不变？是否非单任务操作步骤？全局 `~/.claude/CLAUDE.md` 须四判据全过（见 §2「CLAUDE.md 通用化原则」）
- [ ] **表述规范 §A 已过**：全文对照 §A 歧义层逐条自查（见 §2「表述规范」）
- [ ] **助动词与术语一致**：应/宜/可/不应用法明确（A9），同一概念全文同一术语（A3）

**反模式：**

- 实例化数据（具体主机名、IP、端口）写入面向所有实例的通用文档
- 同一信息在理论文档和操作手册中各写一遍，形成两份权威源
- 只属于某一场景的特化步骤写入通用手册

### 5.2 MODIFY — 修改文档

**检查项：**

- [ ] **未跨层写入**：没把理论/架构内容写进操作手册，没把操作步骤写进理论文档
- [ ] **未回灌上层**：没把具体业务细节（参数、节点名、命令）回灌到上层入口索引
- [ ] **链接可达**：新增的链接已验证目标存在
- [ ] **相邻入口清晰**：修改后，读者仍能从本文档找到相邻的兄弟文档
- [ ] **风格一致**：新增内容的占位符风格、命名惯例与文档现有内容一致
- [ ] **通用化检查（仅 CLAUDE.md）**：新增内容是否跨 2+ 场景、确定后基本不变、非单任务操作步骤？全局 `~/.claude/CLAUDE.md` 须四判据全过（见 §2「CLAUDE.md 通用化原则」）
- [ ] **表述规范 §A 已过**：新增/改写段落对照 §A 歧义层逐条自查（见 §2「表述规范」）

**反模式：**

- 凭证/安全相关文档中混入架构拓扑说明（职责跨层）
- 通用文档中部分命令用占位符、部分硬编码具体值（风格不一致）
- 上层入口因"顺手"被塞入具体操作步骤

### 5.3 RENAME — 重命名文档

**检查项：**

- [ ] **引用全扫**：运行 `docs-graph.py backlinks <旧文件>` 查出所有反向引用（工具不可用时，全局 grep 旧文件名为兜底）
- [ ] **先修后改**：替换所有引用后，再执行重命名
- [ ] **零残留确认**：重命名后再次全局搜索旧文件名，确认无遗漏
- [ ] **索引同步**：入口索引、README、共享索引、兄弟文档中的入口条目已全部更新

**反模式：**

- 只改文件名不修引用，留下断链
- 仅修改本目录的引用，漏掉跨目录或跨项目引用

### 5.4 ARCHIVE — 归档文档

**检查项：**

- [ ] **归档声明**：文档顶部写明归档原因和当前替代入口
- [ ] **入口摘除**：主入口索引不再将其作为一线手册暴露
- [ ] **历史保留**：有价值的历史背景保留到归档目录或 Issue，而非直接删除
- [ ] **反向链接**：如已被新文档取代，从归档文档反向链接到当前权威入口

**反模式：**

- 归档后不清理入口索引，读者仍会被导航到已废弃的文档
- 直接删除而非归档，丢失历史决策背景

### 5.5 RESTRUCTURE — 目录重组 / 索引重建

**检查项：**

- [ ] **框架先行**：如项目有文档框架文件，先读取其层位定义和收敛规则
- [ ] **动作明确**：明确本次操作属于：新增索引 / 合并索引 / 拆分目录 / 归档迁移 / 层级调整
- [ ] **全局扫描**：运行 `docs-graph.py check` 确认移动后无断链（工具不可用时，全局引用扫描为兜底）
- [ ] **根级意识**：根级文档的变更影响多个子项目，不能当局部问题处理
- [ ] **验收基准**：重组后仍满足"通常 3 跳内定位目标文档"

**反模式：**

- 大规模移动文件后不做全局引用扫描
- 重组只考虑当前目录，忽视对兄弟目录和上层索引的连锁影响

### 5.6 DEDUP — 定期查重

存量重复低频偶发，靠定期人工审计清理即可，不做阻断式门禁（增量撞车已由 recall-gate 写时召回覆盖）。

**发现入口：**

- 运行 `docs-graph.py orphans` 列零入链文档——重复副本因无人引用，常成对落入孤儿列表，这是最低成本的发现入口
- 跨项目场景：扫描根覆盖到 monorepo 顶层（`docs-graph.py --root <顶层> orphans`，rglob 递归跨子仓库）；辅以人工 / LLM 审计可疑相似对

**处置流程**（对每对确认的重复）：

1. **判定权威源**：内容更全 / 更新 / 位置更合理的一份为权威源
2. **选动作**：删副本 / 合并差异到权威源 / 都不权威则抽取到 shared 层
3. **引用收口**：`docs-graph.py backlinks <副本>` 查反向引用，全部改指权威源（祈使式引用见 §2）
4. **断链验证**：`docs-graph.py check` 确认零断链

**检查项：**

- [ ] **候选已筛**：跑过 orphans 取候选，并人工判定哪些是真重复（排除 ops 配置 / 命令片段的固有复用）
- [ ] **权威已定**：每对重复已定权威源并执行处置（删 / 合 / 迁）
- [ ] **引用已收口**：副本的所有反向引用已改指权威源（`docs-graph.py backlinks` 查证）
- [ ] **断链已验**：`docs-graph.py check` 确认无断链
- [ ] **跨项目已覆盖**：跨项目重复的扫描根已覆盖所有相关子仓库

**反模式：**

- 把去重做成阻断式硬门禁（增量 recall-gate 已覆盖、存量低频，硬门禁是解决臆想威胁）
- 删副本不收口引用，留下断链
- 跨项目重复只在单仓库内扫，漏掉分属不同子仓库的副本
- 把固有复用（占位符路径、无版本漂移的命令片段）误判为待治理重复
