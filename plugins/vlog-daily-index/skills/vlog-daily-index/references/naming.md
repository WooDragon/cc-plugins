# 每日目录命名与受控迁移

目录名格式为`YYYYMMDD_主行程区域_主题1-主题2[-主题3]`。主行程区域是用户或当前已确认行程给出的固定前缀，不能为追求简短而丢掉大区域；同一行程可沿用，不同项目重新确认，禁止从上一旅行串用。示例：`20300102_示例主行程_峡谷-雪山-徒步`。示例区域和日期不是默认值。

Sol high从已审过的事件、兴趣点、地理结论及原始证据中挑2–3个当日主要景物或活动，ROOT核验代表性、依据与简洁性。使用稳妥的通名，不用未确认峰名/岛名，不把全行程站点塞入每日目录。不为命名重新抽帧、识图或转写。`main_region`不能由GPS单点或每日主题偷偷替换。

## 固定入口与授权

使用`scripts/vlog_daily_index.py`的`naming-plan`、`naming-review`、`naming-apply`；参数以相应`--help`为准。命名配置是普通JSON，例如：

```json
{
  "date": "2030-01-02",
  "main_region": "示例主行程",
  "themes": ["峡谷", "雪山", "徒步"],
  "reviewer": "ROOT",
  "reason": "已核对当前行程与审过的日级证据，主题代表当日主要内容"
}
```

`naming-plan --state STATE --config NAMING_JSON --library-root LIBRARY_ROOT --index INDEX_CSV`仅生成并保存dry-run计划，不移动业务目录或修改库索引。检查建议目录名、源/目标、索引变更和受影响状态；`naming-review --state STATE --plan PLAN_JSON --reviewer ROOT --reason EVIDENCE`记录ROOT对该计划摘要的核验。改动配置或计划后须重新生成/核验，不能沿用旧确认。

只有用户已授权该次目录改名，或已明确授权此任务自动按规则命名/改名，才运行`naming-apply --state STATE --plan PLAN_JSON`。已有授权时不逐次再问；ROOT核验是Agent内部质量门槛，不是用户授权的替代。本轮仅更新Skill或请求建议时，到dry-run为止。

## 依赖顺序与边界

先完成已有语义/地理结果与ROOT证据审查，再选每日主题并生成计划。实际迁移限定受控库根内同父目录重命名，并同步支持的现有CSV索引路径；不跨卷搬运、不重排整库、不改全库规范或其他Skill。冲突、越界、链接或未识别的索引结构必须停止，不强行覆盖。

当前支持UTF-8 BOM编码与十列表头：`路径,原名,来源,大小,SHA256,校验,状态,配套,关联,备注`；路径值为相对`library_root`的POSIX路径。仅`路径/配套/关联`中属于本次源根的单路径值可更新；来源、原名、大小、hash、校验状态和备注保持原值，库内其他目录引用不动。绝对路径、越界值或混合多路径不在本工具支持范围内。CSV在提交前后按内容摘要核对；外部并发修改不能被覆盖。实际apply目前仅支持Windows，其他平台不宣称实测或可迁移执行。

迁移只更新当前manifest的源根及相关物理路径，并记录`path_rebindings`。`source_id`、相对文件名、帧/包ID、成功转写与缓存键保持原值；历史包里的原绝对路径是历史证据，不能重新probe来生成新身份，也不能广泛替换非源树的FIT或本地状态路径。

迁移后既有发布批准失效；复用当前已验证语义和证据，重新生成本地三成果，完成受影响的ROOT审查与hash绑定，再发布到新根并回读。命名本身不构成重跑媒体或全量模型分析的理由。最终成果仍仅原有三文件，命名计划/journal留在本地state，不发布私人运行状态。

## 中断恢复

同一state只运行一个修改命令。保留原计划与迁移journal，使用同一`naming-apply --plan`恢复；工具依据源/目标目录身份和已完成阶段继续，不手动重复改名，不另造新计划绕过未完成迁移。若源/目标同时异常、身份不一致或索引无法核对，先停止并核实。恢复后检查manifest当前根、索引路径、源/侧车可读性及发布批准失效，再按正常终审/发布链继续。不要重新init，也不要用旧根发布。
