# 必需行程与专门地点关联（v0.1.1）

## 先找到本次行程

行程是最终交付的必需输入。先检索当前聊天、本项目已有相关聊天与资料，再检索用户已连接的Notion。聊天可用harness的列表/读取接口；Notion使用实际可用的search/fetch连接器。检索以日期、目的地、路线及本项目名称为边界，不擅自扩大到无关私人资料。脚本不连接聊天或Notion，也不伪造“已检索”。

保留来源的标题、可回查引用、支持路线的原文摘录；区分计划路线、实际执行及后续更改。有来源冲突时记录冲突并结合已发生事件/GPS核实。文件夹日期、文件名、地图搜索结果均不能自行充当行程。确实找不到、无访问权限或无法消解重要冲突时与用户讨论，不能静默省略或把最终报告降级成“未提供行程”。寻找行程期间可复用已完成媒体工作，不重抽/重转写。

输入为一个本地JSON快照，最小结构：

```json
{
  "title": "本次路线（示例）",
  "source_refs": [{"id": "route-source-1", "kind": "notion", "reference": "可回查的页面引用", "excerpt": "支持该路线的原文摘录"}],
  "entries": [{"id": "route-day-1", "date": "2030-01-02", "place": "示例湖区", "notes": "计划与实际状态、路线顺序及不确定性", "source_refs": ["route-source-1"]}]
}
```

`kind`按真实来源记录；日期无法核实时为null，不能仅据归档日期补成确定日期。不要把真实行程、Notion页面内容、查询坐标或凭据打入分发Skill。

## 从拍摄时刻和GPS到地图证据

先用文件内时码+可信拍摄起点/正常播放倍率得到拍摄时刻，再取得该时刻相机/记录者位置。无人机优先自身SRT；Garmin不跨120秒缺口、不外推。用户提供本行程GPS已确认随行；未知时钟或倍率时不能制造精确坐标，可结合路线顺序与相邻可信记录提出有依据的大概区域，明确降低精度和置信度。

在具备合法可用工具/凭据时，使用高德或类似地图接口查询已取得的坐标与周边地点；缓存实际查询证据供专门agent引用。记录提供商、接口类型、查询时间、原坐标/CRS、实际查询坐标/CRS、必要转换依据、脱敏请求、响应、候选和精度。坐标转换不能通过改一个CRS标签冒充。高德提供GPS等外部坐标到高德坐标的[官方转换接口](https://developer.amap.com/api/webservice/guide/api/convert)，[逆地理接口](https://lbs.amap.com/api/webservice/guide/api/georegeo)返回结构化地址及周边POI/AOI；按目标接口的坐标规范查询。

API key等凭据只通过授权工具或运行环境临时使用，不写入manifest、任务包、缓存或日志。缓存必须脱敏，不记录含key/token的原始URL。找不到可用地图接口或凭据时保留已完成工作并与用户讨论，不能把普通网页猜测伪称已成功逆地理查询。

逆地理地址表示查询坐标附近，不等于画面远方主体。近处道路/湖岸名称与远景雪山/山峰名应分别判断；不能把最近POI当唯一正确景点。结合路线、拍摄时间、GPS、已有画面观察和转写建立推断；需要时保留多个候选及排除理由。

## 先事件兴趣点，再专门Sol地理关联

Luna保持逐图观察职责；Sol high先生成跨文件事件/兴趣点。之后必须安排一个专门的`gpt-6.1-sol`、high agent处理地点关联，输入既有daily、必需行程、GPS/停留、地图查询缓存、已校验观察与完整转写。不改写既有事件/兴趣点的语义、原话归属或帧/包身份，复用既有有效证据，不全量重看或重跑ASR。ROOT最后审查位置推断、候选和原有纠正决定。

地点输出独立保存于`geography`，不污染原`location`中逐字引用的精确GPS记录。每个事件和兴趣点都必须对账：可以resolved、approximate或unresolved，不能悄悄漏掉困难条目。输出包含地区/地点名、对象类型（拍摄位置或远景主体）、confidence、推断理由、已有媒体证据ID、行程来源引用、GPS/地图引用及替代候选；无法可靠确定时保留明确unresolved和原因。近似推断是合法结果，不能一律写null；也不能把路线计划当作已经到达的事实。

画面视觉重心是地标或自然景观、仅GPS不能确认身份时，专门agent必须做专项主体核验：先复用Luna标记/既有关键帧，结合可信拍摄时刻、相机/记录者GPS、可用朝向、路线和地形/地图资料，给主体描述、身份候选、支持/反证和缺证据。雪山、湖岛、沟槽等远景不能用相机最近地址代称；朝向缺失就写缺失，不捏造。仅在现有证据不足且有较强错漏线索时提出具体区间补采候选，ROOT决定是否采纳；一轮局部证据回流后只更新受影响事件/地理依赖，不全量重审。

流程入口：

```text
attach-itinerary --state STATE --itinerary ITINERARY_JSON --map-evidence MAP_CACHE_JSON
geography-package --state STATE --daily DAILY_JSON
专门Sol high读取包并写指定result_path
import-geography --state STATE --result GEOGRAPHY_RESULT_JSON
render --state STATE --daily DAILY_JSON
final-review-package --state STATE
ROOT综合审阅并填写固定模板后approve-final --review-result FILE，再publish
```

脚本仅做输入/引用/全条目覆盖/摘要绑定与报告渲染，语义地理判断由专门agent完成；不新增地理编码框架或服务。地理结果绑定当前daily、行程和地图/GPS证据摘要；任何输入变化使旧关联与最终批准失效，须定向重新关联和审查，不重跑已成功媒体阶段。旧v0.1.0运行用attach入口迁移，保留既有状态和已发布版本。
